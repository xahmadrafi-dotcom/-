# মেটাডেটা ব্যবস্থা নির্দেশিকা

---

## উদ্দেশ্য

এই নির্দেশিকা M99 প্রকল্পের সকল নথিতে ব্যবহৃত মেটাডেটা ব্যবস্থার বিবরণ দেয়।
প্রতিটি ফাইলের শুরুতে front matter, ভার্সন লগ স্কিমা, এবং নোড শনাক্তকারী তথ্য কীভাবে সাজাতে হবে—তা এখানে সংজ্ঞায়িত করা হয়েছে।

---

## প্রযোজ্য ক্ষেত্র

- Markdown ফাইলের YAML front matter
- নোড ফাইল (`nodes/*.md`)
- ভার্সন লগ এন্ট্রি
- হ্যান্ডঅফ টেমপ্লেট
- যেকোনো নথি যেখানে M99 প্রকল্পের তথ্য সংরক্ষিত থাকে

---

## ব্যবহার পদ্ধতি

### মূল front matter কাঠামো

প্রতিটি গুরুত্বপূর্ণ Markdown নথির শুরুতে নিচের কাঠামো ব্যবহার করতে হবে:

```yaml
---
project: "M99"
document: "নথির নাম"
version: "ঐ ০.০১"
status: "Draft"
updated: "YYYY-MM-DD"
classification: "Internal"
---
```

### নোড মেটাডেটা কাঠামো

প্রতিটি নোড ফাইলের জন্য:

```yaml
node_id: "kebab-case-id"
name_bn: "বাংলা নাম"
type: "node_type"
core: "মূল বার্তা এক বাক্যে"
formula: "ধাপ১ → ধাপ২ → ধাপ৩"
symbols:
  - "প্রতীক১"
  - "প্রতীক২"
```

### ভার্সন লগ এন্ট্রি কাঠামো

```json
{
  "date": "YYYY-MM-DD",
  "version": "ঐ X.XX",
  "type": "যোগ | সংশোধন | পুনর্গঠন",
  "title_bn": "বাংলা শিরোনাম",
  "title_en": "English title",
  "items": ["পরিবর্তন ১", "পরিবর্তন ২"]
}
```

---

## সতর্কতা

- `version` ক্ষেত্রে সর্বদা ঐ-ভার্সনিং ব্যবহার করতে হবে (যেমন: `ঐ ০.০১`)।
- `status` কেবল `Draft`, `Review`, বা `Final` হতে পারে।
- `updated` ক্ষেত্রে ISO 8601 তারিখ বিন্যাস (`YYYY-MM-DD`) ব্যবহার করতে হবে।
- `classification` ক্ষেত্রে কেবল `Internal` বা `Public` মান গ্রহণযোগ্য।
- নোড `type` সংক্ষিপ্ত ইংরেজি হবে, কিন্তু `name_bn` এবং `core` বাংলায় হবে।

### ধূমকেতু-সত্তা নোডের মেটাডেটা:

```yaml

name_bn: "ধূমকেতু-সত্তা"
type: "symbolic_identity"
core: "দহন থেকে রূপান্তর, রূপান্তর থেকে আলো"
formula: "দহন → রূপান্তর → আলো"
symbols:
  - "ধূমকেতু"
  - "আগুন"
  - "অন্ধকার"
  - "আলো"
```
